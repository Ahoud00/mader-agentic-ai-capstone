# نموذج التهديد والخصوصية — Madar

## الأصول الحساسة
| الأصل | المكان |
|---|---|
| مفتاح OpenRouter | `.env` فقط (مستثنى في `.gitignore`، ولا يُطبع ولا يُعرض في الواجهة؛ `server.py` لا يعيد الرسائل الكاملة) |
| بيانات المستخدم الشخصية (الاسم، البريد، الجدول، الميزانية) | `my_context.text` |
| جهات الاتصال (بريد المشرف وإدارة المعسكر) | `my_context.text` |
| سجل التنبيهات | `data/alerts.jsonl` |
| System prompt / AGENTS.md | يُحمّل في الذاكرة |

## المدخلات غير الموثوقة
1. نص المستخدم في الواجهة أو الـ API (حقن مباشر).
2. محتوى الملاحظات في `data/notes/` (قد يأتي من أطراف خارجية، مثل ملاحظة من مورد): **حقن غير مباشر**.
3. مخرجات الأدوات، بما فيها نتائج خادم MCP.

## مسارات إخراج البيانات (Egress)
1. **`create_alert` (MCP)**: المسار الوحيد للكتابة. يستطيع المهاجم محاولة وضع البيانات الشخصية في التنبيه وتوجيهه لمستلم خارجي.
2. رد الوكيل للمستخدم: قد يكشف بيانات أكثر من المطلوب.
3. الطلبات إلى OpenRouter: كل سياق المحادثة يُرسل لطرف ثالث (النموذج).

## الدفاعات البرمجية (لا تعتمد على System Prompt)
| الطبقة | التنفيذ |
|---|---|
| فحص المدخل | `inspect_input_for_injection`: تطبيع Unicode، إزالة المحارف الخفية، قائمة عبارات |
| تعقيم مخرجات الأدوات | `sanitize_tool_output`: حذف الأسطر التي تشبه تعليمات موجهة للوكيل، وتغليف الباقي في `<untrusted_data>` |
| سياسة الإخراج | `check_egress_policy`: قائمة سماح للمستلمين، ومنع البريد والهواتف وما يشبه الأسرار في نص التنبيه. تُطبق **قبل** البوابة البشرية |
| البوابة البشرية | كل أداة كتابة تتوقف وتعرض المدخلات كاملة قبل Approve أو Reject |
| حصر الوصول للملفات | `read_note` يقرأ فقط من داخل `data/notes` (منع path traversal) |
| حدود | `MAX_STEPS=6`، واقتطاع مخرجات الأدوات إلى 3000 حرف |

## الخصوصية ونظام حماية البيانات الشخصية (PDPL)
إجراءات مطبقة تتماشى مع مبادئ نظام حماية البيانات الشخصية السعودي. **هذا ليس ادعاءً بالامتثال القانوني الكامل**، فالامتثال يتطلب مراجعة قانونية وإجراءات تنظيمية لم تُنفذ هنا.
- **تقليل البيانات:** كل البيانات في المشروع اصطناعية. الوكيل يقرأ ملفًا محليًا واحدًا وملاحظات محددة فقط.
- **تحديد الغرض:** الأدوات محصورة في وظائف الإنتاجية. لا توجد أداة إرسال بريد حقيقي.
- **الحد من الإفصاح:** سياسة الإخراج تمنع خروج البريد والهواتف إلى مستلمين خارج القائمة.
- **الشفافية والتحكم:** المستخدم يرى مدخلات كل إجراء كتابة ويقرر بنفسه.
- **النقل لطرف ثالث:** السياق يُرسل إلى OpenRouter ومزوّد النموذج (قد يكون خارج المملكة). مع بيانات حقيقية يلزم تقييم النقل عبر الحدود، وموافقة صريحة من صاحب البيانات، واختيار مزوّد مناسب أو نموذج محلي.
- **الاحتفاظ:** `data/alerts.jsonl` محلي ومستثنى من git. لا توجد سياسة حذف آلية (نقص معروف).
- **الأسرار:** المفتاح في `.env` فقط، و`.env.example` بلا قيم حقيقية.
